# Logic Fixes — Round 2 Audit Findings

## Summary
Second-pass logic review found remaining IDOR gaps in running/training APIs, missing FK enforcement (cascades silently ignored), and tree relationship functions without ownership checks.

---

## Fix 1: Enable SQLite Foreign Key Enforcement (CRITICAL)

**Problem:** `PRAGMA foreign_keys = ON` is never set. All `onDelete: 'cascade'` in the schema are silently ignored. Deleting a session leaves orphaned activities, track points, exercise records.

**File:** `src/lib/server/db/index.ts`

**Change:** After creating the libsql client, execute `PRAGMA foreign_keys = ON` via `client.execute()`.

---

## Fix 2: Tree Relationship IDOR — Add userId Verification (CRITICAL)

**Problem:** `addChildToParent`, `removeChildFromParent`, `moveChild` take no userId. Any user can manipulate any other user's tree relationships.

**Files:**
- `src/lib/server/services/tree.service.ts` — add ownership verification to the 3 relationship functions
- `src/routes/api/tree/+server.ts` — pass `user.id` to these functions

**Approach:** For each relationship mutation, verify the child element belongs to the user before modifying the relationship. Also clean up orphaned relationships when deleting elements.

---

## Fix 3: `deleteTreeElement` — Clean Up Relationships (MEDIUM)

**Problem:** Deleting an element leaves orphaned rows in `treeRelationship`.

**File:** `src/lib/server/services/tree.service.ts`

**Change:** Before deleting the element, delete all relationships where it is parent or child.

---

## Fix 4: Running API — Add userId Checks (HIGH)

**Problem:** All running API endpoints accept raw activityId/sessionId with no ownership verification. Any user can read/write/delete another user's GPS track points.

**File:** `src/routes/api/running/+server.ts`

**Approach:** For every endpoint that takes `sessionId` or `activityId` from user input, verify the session belongs to `user.id` before proceeding. Add a helper `verifyRunningOwnership(userId, activityId)` to `running.service.ts`.

---

## Fix 5: Training linkItemToActivity/unlinkItemToActivity/getActivityItems — Add userId (HIGH)

**Problem:** These functions take only `activityId` with no userId check.

**Files:**
- `src/lib/server/services/training.service.ts` — add userId param and ownership check
- `src/routes/api/training/+server.ts` — pass `user.id`

---

## Fix 6: createPage — Verify Category Ownership (MEDIUM)

**Problem:** `createPage` accepts any `categoryId` without checking it belongs to the user.

**File:** `src/lib/server/services/page.service.ts`

**Change:** Before inserting, verify the category belongs to `userId`.

---

## Fix 7: Security Headers for /api/auth (MEDIUM)

**Problem:** `/api/auth` returns early before security headers are set.

**File:** `src/hooks.server.ts`

**Change:** Move security headers into a wrapper applied after the resolve, before the final return — or apply them in both the auth path and the normal path.

---

## Fix 8: Stats Page userId Filter (LOW)

**File:** `src/routes/app/training/stats/+page.server.ts`

**Change:** Add `.innerJoin(trainingSession, ...).where(eq(trainingSession.userId, locals.user.id))` to the running data query.

---

## Fix 9: Rate Limiter — Prevent Interval Leak (LOW)

**File:** `src/lib/server/rate-limit.ts`

**Change:** Guard the `setInterval` with a check to avoid duplicates on HMR, or use `globalThis` to store the interval ID.
